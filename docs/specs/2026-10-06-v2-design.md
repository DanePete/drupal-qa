# drupal-qa v2: design

> **Historical.** The design as proposed on 2026-10-06. drupal-qa now ships from
> `DanePete/drupal-qa` as the Composer package `thronedigital/drupal-qa`; read that wherever this
> says `augustash/drupal-qa`. The [README](../../README.md) describes what was built.

**Status:** proposed, 2026-10-06. **Repo:** `augustash/drupal-qa` (copied from `DanePete/drupal-qa`).

## Principles

1. **Easy, or nobody adopts it.** One file, same for every site except its name.
2. **Not policing, or nobody adopts it.** Checks warn by default. Teams opt in to blocking, by name.
3. **It has to actually work.** v1 shows green while Behat has never run a scenario and Gitleaks has
   never scanned (both on mnair, from the run logs). v2 never reports a step that did not run as a pass.

## Install

1. `composer require --dev augustash/drupal-qa` (scaffolds `phpunit.xml.dist`, `phpstan.neon.dist`, `behat.yml.dist`).
2. Commit `.github/workflows/drupal-qa.yml`:

   ```yaml
   name: Drupal QA
   on:
     pull_request: { types: [opened, synchronize, reopened, closed] }
     push: { branches: [main] }
   jobs:
     qa:
       uses: augustash/drupal-qa/.github/workflows/pipeline.yml@v2
       with:
         pantheon_site: my-site
       secrets: inherit
   ```

3. Secrets `PANTHEON_MACHINE_TOKEN` and `PANTHEON_SSH_KEY`. Set once at org level, step 3 disappears.

`secrets: inherit` only reaches across repos in the same org; outside augustash, pass the two secrets by name.

## Inputs

All optional except `pantheon_site` (not needed when `code_host: none`).

| Input | Default | Meaning |
|---|---|---|
| `required` | *(empty)* | Checks that block, e.g. `phpcs phpunit` |
| `skip` | *(empty)* | Steps that don't run, e.g. `behat cim` |
| `code_host` | `pantheon` | `pantheon` (we push), `github-app` (Pantheon's app pushes), `none` (checks only) |
| `multidev` | `true` | `false` for sites below Gold: PRs get checks only |

Names usable in `required` / `skip`: `phpcs phpstan yamllint audit secrets phpunit behat config`
(`config` is the post-deploy `config:status`). `updatedb` and `cim` can be skipped, never downgraded:
when they run, a failure fails the run, because the site is broken.

Detected, not configured: PHP version (`composer.json` `config.platform.php`, else 8.3); PHPCS paths
(`web/modules/custom` plus every theme directory that is not `contrib`); the commerce Behat suite (when
`drupal/commerce` is in `composer.lock`); the site UUID (from `terminus site:info`).

## What runs

| Event | Jobs |
|---|---|
| PR opened / pushed | `checks` in parallel with `deliver → converge → post-deploy → verify` on `pr-N` |
| Push to main | `checks → deliver → converge → post-deploy → verify` on `dev` |
| PR closed | `cleanup`: delete `pr-N` (`pantheon` only) |

- **checks**: PHPCS, PHPStan, yamllint on `config/`, `composer audit`, Gitleaks (CLI binary, which is free for
  orgs; the Action is not), PHPUnit unit + kernel + package smoke tests.
- **deliver**: `pantheon` creates the multidev if needed and pushes; on main it first refuses if Pantheon's
  master is not an ancestor (dashboard commits). `github-app` and `none`: nothing.
- **converge**: wait until the environment's container serves this commit: `workflow:wait` as a hint, then
  poll the md5 of a file the commit changed (`scripts/deploy-without-actions.sh` on mnair), 15 min limit.
  On `github-app`, first wait for Pantheon to create the environment.
- **post-deploy**: `updatedb` (retried once on exit 137), `config:import`, `cache:rebuild`.
- **verify**: `config:status` must be empty; Behat smoke against the environment URL.
- With `code_host: github-app` on main, Pantheon deploys whatever merges; only branch protection can stop a merge.

## Reliability rules

- **Warn is visible.** A warned failure posts an annotation and a row in the run summary; never a silent pass.
- **Crashed or zero tests = failure**, in warn mode too.
- **Delivery queues, never cancels.** `deliver`/`converge`/`post-deploy`/`verify`/`cleanup` share a per-PR
  concurrency group with `cancel-in-progress: false`; `checks` cancel on a newer push. A cancelled
  `multidev:create` strands a half-built environment (mnair, PRs #180, #214, #252).
- **Run summary**: one table of every step (passed / warned / failed / skipped) plus the environment URL.
  The PR comment with the URL stays.

## Package changes

Removed: `scripts/setup.sh`, `scripts/setup-extras.sh`, GrumPHP (installs commit-blocking git hooks
unasked), the `CLAUDE.md` and `copilot-instructions.md` scaffolds (overwrote the project's own),
`scaffold/github/workflows/` (four drifted dead copies), the four v1 entry workflows (v1 tags keep them).

Fixed: Behat (remote environment: blackbox for anonymous, drush driver over the Pantheon alias for login,
base URL via `BEHAT_PARAMS`; if the drush driver proves unreliable over SSH, v2.0 ships the anonymous
scenarios only rather than a flaky login); Gitleaks; `config:status` false positive (matched without the `[notice]`
prefix, so it warned every run); the deploy-to-dev race and `|| true` on `updb`/`cim`; commerce features
running on sites without Commerce; actions bumped (checkout v7, cache v6, github-script v9,
upload-artifact v7); Terminus pinned.

## README

1. What it is, the install (above), the four inputs.
2. **Install with Claude Code**: a self-contained prompt. Claude reads the site name from `.ddev/config.yaml`,
   asks at most two questions (is it on Pantheon's GitHub App? does it have multidevs?), writes the file,
   runs `composer require`, checks the secrets exist (`gh secret list`, repo and org) and gives `! gh secret set`
   commands if not, never handling secret values, and asks before pushing and opening the PR.
3. **Pantheon's GitHub integration vs drupal-qa**: what Pantheon's GitHub App and its `push-to-pantheon` Action
   are and aren't, side by side with drupal-qa. Facts only from Pantheon's docs; anything undocumented
   says so instead of guessing.
4. Troubleshooting, migrating from v1.

## Open, for the GitHub App spike (after the demo)

What the app names a PR's environment, whether it deletes it on close, whether it reports GitHub
deployments (a `deployment_status` trigger would replace polling), and whether Quicksilver hooks fire.
`github-app` mode ships with polling and assumes `pr-N`; the spike confirms or corrects it.

## Changed while building (2026-10-06)

Found by running the pipeline against a real sandbox site (`aa-drupal-qa-demo`) rather than by reading:

- **No scaffolding at all.** CI copies the package's `phpunit.xml.dist`, `phpstan.neon.dist` or `behat.yml.dist`
  when a project has none, so installing no longer needs the drupal-scaffold `allowed-packages` step.
- **Behat config is layered with `imports`, not `BEHAT_PARAMS`.** Behat applies `BEHAT_PARAMS` before the config
  file, so any `base_url` in a file silently won and every request went to localhost.
- **Logging in uses drush, not Drupal Extension's user creation.** From Drupal Extension 5.3, user creation
  calls `isBaseField()`, which its Drush driver does not implement; 6.x requires the local API driver outright.
  The base context creates the user with `drush user:create` and logs in with `drush user:login`.
- **Pantheon's next-generation CDN challenges CI.** Its challenge is a 403 indistinguishable from Drupal's, so
  "anonymous gets 403" passed without reaching Drupal. CI fetches the site's token with
  `terminus gcdn:bot-bypass` and sends `x-pantheon-bot-bypass` on every request; a challenged response fails.
- **yamllint checks only syntax and duplicate keys.** Style rules flagged Drupal's own exports.
- **Terminus quirks:** `env:info --field=initialized` prints `1`; `self:plugin:install` fails when the plugin
  is already installed; `ssh-key:add` rejects ed25519 keys.
- **A new Pantheon site's repo has `main` (the template) and `master` (what dev runs).**
